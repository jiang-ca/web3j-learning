# 一、本节目标

进入余额、交易、Gas、代币数量之前，先统一链上数值的处理方式。

本节要掌握：

```text
JSON-RPC 十六进制 quantity
→ BigInteger
→ Wei / Gwei / BNB 单位换算
→ BigDecimal 精确显示
```

以及明确：

```text
链上原始整数
不要用 double 保存
```

# 二、为什么链上金额首先是整数

EVM JSON-RPC 中大量数量使用十六进制 quantity 表示。

例如：

```text
0xde0b6b3a7640000
```

转换成十进制：

```text
1000000000000000000
```

对于 BSC 原生 BNB，链上金额使用 Wei 作为最小单位。Web3j 的 `Convert.Unit.ETHER` 定义的换算因子是 `10^18`，因此可以用于 BNB 的 18 位原生单位换算。

注意：`ETHER` 是 Web3j 枚举沿用的 Ethereum 命名；在 BSC 场景中，我们使用的是它的 `10^18` 换算因子，最终显示单位是 BNB。

# 三、完整示例

源码：

```text
src/main/java/com/example/web3jstudy/w2/NumberUnitPrecisionDemo.java
```

```java
package com.example.web3jstudy.w2;

import java.math.BigDecimal;
import java.math.BigInteger;

import org.web3j.utils.Convert;
import org.web3j.utils.Numeric;

public class NumberUnitPrecisionDemo {

    public static void main(String[] args) {

        String hexQuantity =
                "0xde0b6b3a7640000";

        BigInteger wei =
                Numeric.decodeQuantity(hexQuantity);

        BigDecimal bnb =
                Convert.fromWei(
                        new BigDecimal(wei),
                        Convert.Unit.ETHER);

        BigDecimal gwei =
                Convert.fromWei(
                        new BigDecimal(wei),
                        Convert.Unit.GWEI);

        System.out.println(
                "RPC 十六进制数量：" + hexQuantity);
        System.out.println(
                "Wei：" + wei);
        System.out.println(
                "Gwei：" + gwei.toPlainString());
        System.out.println(
                "BNB：" + bnb.toPlainString());

        BigDecimal inputBnb =
                new BigDecimal(
                        "0.123456789012345678");

        BigDecimal weiDecimal =
                Convert.toWei(
                        inputBnb,
                        Convert.Unit.ETHER);

        BigInteger inputWei =
                weiDecimal.toBigIntegerExact();

        BigDecimal restoredBnb =
                Convert.fromWei(
                        new BigDecimal(inputWei),
                        Convert.Unit.ETHER);

        System.out.println();
        System.out.println(
                "输入 BNB："
                        + inputBnb.toPlainString());
        System.out.println(
                "转换为 Wei："
                        + inputWei);
        System.out.println(
                "再还原 BNB："
                        + restoredBnb.toPlainString());

        BigDecimal unsafe =
                new BigDecimal(0.1);

        BigDecimal safe =
                new BigDecimal("0.1");

        System.out.println();
        System.out.println(
                "double 0.1 转 BigDecimal："
                        + unsafe.toPlainString());
        System.out.println(
                "字符串 0.1 转 BigDecimal："
                        + safe.toPlainString());
    }
}
```

# 四、十六进制 quantity 与 BigInteger

Web3j 提供：

```java
Numeric.decodeQuantity(hexQuantity)
```

例如：

```text
0xde0b6b3a7640000
↓
1000000000000000000
```

返回类型是 `BigInteger`。

链上很多值本质上都是整数，例如：

```text
区块号
余额
Nonce
Gas
Gas Price
交易 value
Token 原始数量
```

# 五、Wei、Gwei 与 BNB

Web3j 的换算因子：

```text
WEI   = 10^0
GWEI  = 10^9
ETHER = 10^18
```

在 BSC 原生 BNB 场景中：

```text
1 BNB
=
1,000,000,000,000,000,000 Wei
=
10^18 Wei
```

因此可以使用：

```java
Convert.fromWei(
        new BigDecimal(wei),
        Convert.Unit.ETHER
)
```

把最小单位转换为用户可读的 BNB 数值。

Gwei 后面主要用于 Gas Price。

# 六、BigInteger 与 BigDecimal 的职责

## 6.1｜BigInteger

适合保存链上原始整数：

```java
BigInteger wei;
BigInteger blockNumber;
BigInteger nonce;
BigInteger gas;
```

链上不存在小数 Wei。

## 6.2｜BigDecimal

适合：

```text
单位转换
金额显示
带小数的业务输入
精确十进制计算
```

常见数据流：

```text
链上 BigInteger 原始整数
↓
BigDecimal 单位转换
↓
用户显示值
```

# 七、为什么金额不要用 double

```java
new BigDecimal(0.1);
new BigDecimal("0.1");
```

结果不同。

`double` 是二进制浮点数，`0.1` 不能被精确表示。

因此第一种会得到类似：

```text
0.100000000000000005551115123...
```

第二种才是精确的：

```text
0.1
```

链上金额、Gas Price、Token 数量等，不要先经过 `double` 再做精确计算。

# 八、为什么使用 toBigIntegerExact()

```java
BigInteger inputWei =
        weiDecimal.toBigIntegerExact();
```

链上 Wei 必须是整数。

如果转换后出现小数 Wei，`toBigIntegerExact()` 会直接报错，避免静默截断金额。

# 九、原生 BNB 与 Token decimals 不要混为一谈

本节的 `10^18` 针对 BSC 原生 BNB 的单位换算。

后面读取 BEP-20 Token 时，Token 的 `decimals` 由具体合约决定。

不能看到 BSC 上的 Token 就统一假设：

```text
decimals = 18
```

后续课程会直接读取 Token 的 `decimals()`。
