# W2.2｜查询 BNB 余额

状态：🔄 进行中

# 一、本节目标

把 W2.1 的数值处理真正用于链上查询：

```text
BSC 地址
→ eth_getBalance
→ 十六进制 result
→ BigInteger Wei
→ BigDecimal BNB
```

本节查询的是 **BSC 原生 BNB 余额**，不是 BEP-20 Token 余额。

# 二、完整示例

源码：

```text
src/main/java/com/example/web3jstudy/w2/BnbBalanceDemo.java
```

```java
package com.example.web3jstudy.w2;

import java.io.IOException;
import java.math.BigDecimal;
import java.math.BigInteger;

import org.web3j.protocol.Web3j;
import org.web3j.protocol.core.DefaultBlockParameterName;
import org.web3j.protocol.core.methods.response.EthGetBalance;
import org.web3j.protocol.http.HttpService;
import org.web3j.utils.Convert;

public class BnbBalanceDemo {

    public static void main(String[] args) throws IOException {

        String rpcUrl =
                "https://rpc.ankr.com/bsc/替换为你的_API_KEY";

        String address =
                "0x0000000000000000000000000000000000000000";

        Web3j web3j =
                Web3j.build(new HttpService(rpcUrl));

        try {
            EthGetBalance response =
                    web3j.ethGetBalance(
                            address,
                            DefaultBlockParameterName.LATEST)
                            .send();

            if (response == null) {
                throw new IllegalStateException(
                        "RPC 未返回有效响应。");
            }

            if (response.hasError()) {
                throw new IllegalStateException(
                        "查询余额失败，错误码："
                                + response.getError().getCode()
                                + "，错误信息："
                                + response.getError().getMessage());
            }

            String rawResult =
                    response.getResult();

            BigInteger balanceWei =
                    response.getBalance();

            BigDecimal balanceBnb =
                    Convert.fromWei(
                            new BigDecimal(balanceWei),
                            Convert.Unit.ETHER);

            System.out.println(
                    "查询地址：" + address);

            System.out.println(
                    "原始 result：" + rawResult);

            System.out.println(
                    "余额（Wei）：" + balanceWei);

            System.out.println(
                    "余额（BNB）："
                            + balanceBnb.toPlainString());

        } finally {
            web3j.shutdown();
        }
    }
}
```

# 三、eth_getBalance 有两个参数

Web3j 调用：

```java
web3j.ethGetBalance(
        address,
        DefaultBlockParameterName.LATEST)
```

对应 JSON-RPC：

```text
eth_getBalance
```

它包含两个参数：

```text
1. address
2. block parameter
```

本节使用：

```text
latest
```

所以意思是：

> 查询这个地址在最新区块状态下的原生币余额。

历史区块余额查询会在 W2.7 单独学习。

# 四、EthGetBalance 的 result 是什么

响应类型：

```java
EthGetBalance
```

Web3j 中它继承：

```java
Response<String>
```

所以：

```java
response.getResult()
```

得到的仍是 JSON-RPC 原始十六进制 quantity。

而：

```java
response.getBalance()
```

内部会把该 quantity 解码为：

```java
BigInteger
```

单位是：

```text
Wei
```

因此数据流是：

```text
JSON-RPC result
例如 0x...
↓
EthGetBalance.getBalance()
↓
BigInteger Wei
```

# 五、为什么查询结果是 Wei，不直接是 BNB

区块链状态中保存的是整数最小单位。

所以 RPC 返回的是：

```text
Wei
```

而不是已经格式化好的：

```text
1.2345 BNB
```

显示层再转换：

```java
BigDecimal balanceBnb =
        Convert.fromWei(
                new BigDecimal(balanceWei),
                Convert.Unit.ETHER);
```

最终：

```text
链上原始值
→ BigInteger Wei

展示值
→ BigDecimal BNB
```

# 六、eth_getBalance 查询的是原生 BNB

这是本节最重要的边界之一。

假设一个地址持有：

```text
BNB
USDT
USDC
AMP
其他 BEP-20 Token
```

执行：

```text
eth_getBalance
```

只查询：

```text
原生 BNB
```

不会把所有 Token 一起返回。

BEP-20 Token 余额本质上存储在 Token 合约状态里，后续需要调用合约：

```text
balanceOf(address)
```

这是 W3 的内容。

# 七、查询余额不需要私钥

本节只执行：

```text
读取链上公开状态
```

所以只需要：

```text
公开地址
+
RPC
```

不需要：

```text
私钥
助记词
钱包签名
```

因此可以查询任何合法 BSC 地址的余额。

私钥只会在需要：

```text
签名并发送交易
```

时出现，安排在 W5。

# 八、latest 是什么

本节传入：

```java
DefaultBlockParameterName.LATEST
```

Web3j 会把它作为：

```text
"latest"
```

发送给 RPC。

也就是说：

```text
eth_getBalance(
    address,
    "latest"
)
```

这里并不是：

```text
查询地址最后一次交易时的余额
```

而是：

> 使用节点当前的 latest 区块状态查询该地址余额。

后面 W2.7 会进一步比较：

```text
latest
指定历史区块
safe
finalized
```

# 九、预期运行结果

余额本身会随地址和区块状态变化，因此没有固定数字。

输出形式：

```text
查询地址：0x0000000000000000000000000000000000000000
原始 result：0x...
余额（Wei）：...
余额（BNB）：...
```

也可以把示例中的地址替换成你自己的 BSC **公开地址**。

只需要提供地址，不要提供私钥或助记词。
