# W2.3｜查询区块

状态：🔄 进行中

# 一、本节目标

通过 Web3j 调用：

```text
eth_getBlockByNumber
```

读取一个真实 BSC 区块，并理解几个最重要的字段：

```text
区块号
区块 Hash
父区块 Hash
时间戳
交易列表
Gas Limit
Gas Used
```

本节使用最新区块：

```text
latest
```

并设置：

```text
fullTransactionObjects = false
```

因此交易列表只返回交易 Hash。

# 二、完整示例

源码：

```text
src/main/java/com/example/web3jstudy/w2/BlockQueryDemo.java
```

```java
package com.example.web3jstudy.w2;

import java.io.IOException;
import java.time.Instant;
import java.util.List;

import org.web3j.protocol.Web3j;
import org.web3j.protocol.core.DefaultBlockParameterName;
import org.web3j.protocol.core.methods.response.EthBlock;
import org.web3j.protocol.http.HttpService;

public class BlockQueryDemo {

    public static void main(String[] args) throws IOException {

        String rpcUrl =
                "https://rpc.ankr.com/bsc/替换为你的_API_KEY";

        Web3j web3j =
                Web3j.build(new HttpService(rpcUrl));

        try {
            EthBlock response =
                    web3j.ethGetBlockByNumber(
                            DefaultBlockParameterName.LATEST,
                            false)
                            .send();

            if (response == null) {
                throw new IllegalStateException(
                        "RPC 未返回有效响应。");
            }

            if (response.hasError()) {
                throw new IllegalStateException(
                        "查询区块失败，错误码："
                                + response.getError().getCode()
                                + "，错误信息："
                                + response.getError().getMessage());
            }

            EthBlock.Block block =
                    response.getBlock();

            if (block == null) {
                throw new IllegalStateException(
                        "RPC 没有返回区块数据。");
            }

            Instant blockTime =
                    Instant.ofEpochSecond(
                            block.getTimestamp().longValueExact());

            List<EthBlock.TransactionResult> transactions =
                    block.getTransactions();

            int transactionCount =
                    transactions == null
                            ? 0
                            : transactions.size();

            System.out.println(
                    "区块号：" + block.getNumber());

            System.out.println(
                    "区块号原始值：" + block.getNumberRaw());

            System.out.println(
                    "区块 Hash：" + block.getHash());

            System.out.println(
                    "父区块 Hash：" + block.getParentHash());

            System.out.println(
                    "出块时间：" + blockTime);

            System.out.println(
                    "交易数量：" + transactionCount);

            System.out.println(
                    "Gas Limit：" + block.getGasLimit());

            System.out.println(
                    "Gas Used：" + block.getGasUsed());

            if (transactionCount > 0) {
                String firstTransactionHash =
                        (String) transactions.get(0).get();

                System.out.println(
                        "第一笔交易 Hash："
                                + firstTransactionHash);
            }

        } finally {
            web3j.shutdown();
        }
    }
}
```

# 三、ethGetBlockByNumber() 的两个参数

Web3j 方法：

```java
web3j.ethGetBlockByNumber(
        DefaultBlockParameterName.LATEST,
        false)
```

对应 JSON-RPC：

```text
eth_getBlockByNumber
```

两个参数分别解决：

```text
第一个参数
→ 查哪个区块

第二个参数
→ transactions 返回交易 Hash 还是完整交易对象
```

本节：

```text
LATEST
→ 查询最新区块

false
→ transactions 只返回交易 Hash
```

# 四、EthBlock 与 EthBlock.Block

调用：

```java
EthBlock response =
        web3j.ethGetBlockByNumber(...).send();
```

得到的是 RPC 响应对象：

```java
EthBlock
```

真正的区块数据通过：

```java
EthBlock.Block block =
        response.getBlock();
```

取得。

因此关系是：

```text
JSON-RPC Response
↓
EthBlock
↓
result
↓
EthBlock.Block
```

后面的区块号、Hash、交易数组等都从 `EthBlock.Block` 读取。

# 五、区块号与区块 Hash

## 5.1｜区块号

```java
block.getNumber()
```

得到：

```java
BigInteger
```

这是已经从 JSON-RPC 十六进制 quantity 解码后的十进制区块高度。

原始值：

```java
block.getNumberRaw()
```

例如：

```text
0x785....
```

因此你又会看到 W2.1 的数据模式：

```text
RPC 十六进制 quantity
↓
BigInteger
```

## 5.2｜区块 Hash

```java
block.getHash()
```

区块 Hash 可以理解成这个区块内容对应的哈希标识。

区块号和区块 Hash 不要混为一谈：

```text
Block Number
→ 区块高度 / 位置

Block Hash
→ 该区块内容对应的哈希标识
```

同一个正常链视图中，每个高度对应当前认可的区块 Hash。

后面学习 Reorg 时，会专门处理：

```text
同一个区块高度
但观察到不同 Block Hash
```

的情况。

# 六、父区块 Hash

代码：

```java
block.getParentHash()
```

代表当前区块引用的前一个区块 Hash。

关系可以表示为：

```text
Block N
parentHash
↓
Block N - 1 的 hash
```

因此区块不是互不相关的数据，而是通过 Hash 前后连接。

后续可靠采集阶段判断链重组时：

```text
blockNumber
blockHash
parentHash
```

都会非常重要。

# 七、时间戳

Web3j：

```java
block.getTimestamp()
```

返回：

```java
BigInteger
```

数值是 Unix 时间戳，单位为秒。

示例中转换为：

```java
Instant blockTime =
        Instant.ofEpochSecond(
                block.getTimestamp().longValueExact());
```

这样输出会类似：

```text
2026-10-07T08:30:00Z
```

这里的 `Z` 表示 UTC。

它是区块自己的时间戳，不是 Java 程序收到 RPC 响应的本地时间。

# 八、transactions 与 fullTransactionObjects

这是本节一个重要参数。

调用：

```java
ethGetBlockByNumber(..., false)
```

时，区块中的：

```text
transactions
```

只包含交易 Hash。

例如：

```text
0xabc...
0xdef...
0x123...
```

所以：

```java
block.getTransactions().size()
```

可以得到该区块包含多少笔交易。

本例还打印：

```text
第一笔交易 Hash
```

下一节 W2.4 会拿一个交易 Hash，再调用：

```text
eth_getTransactionByHash
```

查询完整交易内容。

# 九、如果第二个参数改成 true 会怎样

如果：

```java
web3j.ethGetBlockByNumber(
        DefaultBlockParameterName.LATEST,
        true)
```

RPC 会要求：

```text
transactions
→ 返回完整交易对象
```

而不是只有 Hash。

因此：

```text
false
→ 返回数据更小
→ 适合只需要交易 Hash 的场景

true
→ 每笔交易包含完整字段
→ 返回数据更大
```

本教程刻意使用：

```text
false
```

因为 W2.4 会单独学习交易对象，避免把两个知识点混在一节。

# 十、Gas Limit 与 Gas Used

区块中还有：

```java
block.getGasLimit();
block.getGasUsed();
```

可以先这样理解：

```text
Gas Limit
→ 这个区块允许容纳的 Gas 上限

Gas Used
→ 这个区块中的交易实际消耗的 Gas 总量
```

它们都是整数。

Gas 的计费、Gas Price 和手续费会在 W5 展开，本节只认识区块字段。
