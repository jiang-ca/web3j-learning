# 三、自定义 HTTP 超时

Web3j 的 `HttpService` 可以接收自定义 `OkHttpClient`。

示例：

```java
OkHttpClient httpClient =
        HttpService.getOkHttpClientBuilder()
                .connectTimeout(5, TimeUnit.SECONDS)
                .readTimeout(15, TimeUnit.SECONDS)
                .writeTimeout(15, TimeUnit.SECONDS)
                .callTimeout(20, TimeUnit.SECONDS)
                .build();

HttpService httpService =
        new HttpService(rpcUrl, httpClient);

Web3j web3j =
        Web3j.build(httpService);
```

# 四、几个超时分别解决什么

`connectTimeout`

→ 建立 TCP / TLS 连接的最大等待时间。

`readTimeout`

→ 连接建立后，等待服务端返回数据时的读取超时。

`writeTimeout`

→ 向服务端写入请求数据的超时。

`callTimeout`

→ 一次完整 HTTP Call 的总时间上限。

实际工程不能只依赖默认值，应根据 RPC 服务、业务类型和重试策略统一配置。

# 五、客户端生命周期

推荐：

```text
应用启动
→ 创建 Web3j 客户端
→ 多个 RPC 查询复用客户端
→ 应用结束
→ shutdown()
```

而不是每执行一个业务方法都重新创建一套 Web3j / HttpService。

Web3j 5.0.3 的 `shutdown()` 会关闭 Web3j 内部调度线程并调用底层 Service 的 `close()`。

它关闭的是本地客户端相关资源，不是关闭 Ankr，也不是关闭 BSC 节点。
